# Independent RULER Variable Tracking NORMAL release

`RULER_INDEPENDENT_CURRENT_V1` is a separate finite six-case authority:
`RulerClassic202`, `RulerDeltanet202`, `RulerClassic303`,
`RulerDeltanet303`, `RulerClassic404`, `RulerDeltanet404`.
The first prefix is empty; subsequent cases require exactly the earlier RULER
cases, in order, through ordinary whole-object replay. Sorting, MQAR and Tiny
receipts are not scientific predecessors. Historical profiles are unchanged.

## Source and review boundary

`build_ruler_training_request.py` reuses the authenticated Tiny lifecycle,
verifies all 71 wheel Python members against current scientific source, copies
current wrappers, and stages `meta.json` and all six arrays in `data/ruler`.
No raw text file or MQAR manifest is required. The resulting source identity and
ZIP digest are real builder outputs, not launch authority. The selected profile
pins that exact package and wheel; it does not use the historical wheel constant.

Pass the genuine request, approved recipe, runtime record, generation intent and
empty/complete prefix to the existing `unified_normal_operator.py` through its
`--inputs`, `--normal-archive` and create-only `--output` interface. The finite
scope authenticates the direct user-permission receipt and the complete prepared
scientific configs (excluding only runtime data mount). Data generation, native
model math, optimizer, RNG, budgets and dependencies are not changed.

Without genuine `normal_review` and `normal_decision` inputs, emission deliberately
produces `UNBOUND_REVIEW_AND_DECISION_REQUIRED`. Public `check`, `next` and
`make-plan` remain read-only. Preparation, probes, seals, services and mutations
reject UNBOUND authority before SDK entry or caller review/private reads.
The saved kernel selects `release/data/ruler` and stops at the same missing typed
review before setup. A hardware facade proves this route, not CUDA qualification.

A raw NORMAL source/plan review and a canonical singleton review are different
subjects. The implementation owner does not issue either review. Commit/hooks,
BOUND rebuilding, fresh LIVE gates and provider mutation belong to the parent
only after independent inspection. No retry/replacement is implied by this release.

## Generated quality and cached acceptance

Only the cloud task phase loads the final `out/model.pt` through unchanged native
`load_evaluation_model`, after `verify_native`. Exactly one unchanged native
`generated_metrics` call uses CUDA float16, batch 32 and all VAL rows. A removable
per-model standard forward hook returns `None`, checks native prefix/feedback
order and records the actual full-vocabulary last-logit argmax. It neither changes
forward outputs nor runs another generation. Non-variable but in-vocabulary
predictions remain valid low-quality outcomes. Nonfinite logits fail natively.

The report binds ordered predictions, complete native metrics, labels/input/meta
hashes, final parameter fingerprint, separate weights-file hash, provenance,
source, config, last step and full budget. HOST and finish reconstruct it using
NumPy and the native prompt oracle, not a model. Link correctness follows prompt
edges between successive predictions, not ground-truth answer adjacency. Primary
quality is `generated_chain_exact_match`; neither TEST nor best checkpoints are
selected. Teacher-forced history remains diagnostic only.

Training ClearML remains auxiliary and enabled. RULER uses the explicit scope
`NATIVE_CLOUD_GENERATION_NO_SEPARATE_INFERENCE_SERVICE`, with diagnostic status
`not_required`: native generation really occurs, but no separate inference
ClearML service is claimed or queried. Native quality and private immutable HF
publication remain hard requirements.

The V5 HOST reader inventories its new tracking helper. Historical V4 receipts
authenticate the original four files, as V2/V3 do, not newly edited reader bytes.
Ordinary FULL replay recognizes authenticated flat `step_XXXXXXXX.pt` callback
files as well as nested final copies, deduplicates identical bytes, and checks
the complete native callback step grid.
