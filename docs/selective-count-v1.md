# Selective Count v1: локальный кандидат

Статус: данные и публичный путь реализованы. Бюджет, научный протокол и облачный оператор требуют проверки родителем. Запуск в облаке не разрешён. Этот этап не разрешает Permutation.

## Задача

Источник: `On-Point-RND/transformer-architecture-generalization`, commit `444bf8466d26b39ea5df90ae0016c62e53392b1f`; исходные файлы и SHA256 находятся в `local/reports/four-task-benchmark/upstream/pins.json`.

- Вход содержит 512 символов из диапазона 1…32. PAD=0 зарезервирован и не генерируется.
- Последний символ является запросом. Ответ — число его появлений во всём входе, включая сам запрос.
- Ровно одна метка находится на позиции 511. Остальные метки равны -1. Ответ не входит во входной массив. Сдвиг next-character не используется.
- `CLASS_LOW=33`; метка равна `33 + count`. Сохранены исходные ID: полный словарь 0…545, размер 546. Диапазон выходных классов 33…545 соответствует декодированным значениям 0…512; правильные ответы имеют count≥1.
- Неизменённый trainer считает same-position cross-entropy по меткам, отличным от -1. Новая loss-функция, архитектура и цикл не добавлены.

## Явные адаптации

У источника m=32 и count_ratio=10 дают n=320. Его `seq_len` явно допускает 512, и `collate` допускает один ответ при block_size=512. Здесь n=512 сохраняет общий контекст и архитектуру. Это изменение сложности, не побайтовое воспроизведение набора с исходными defaults.

Источник использует один `default_rng(seed)`, формирует validation перед train и поддерживает онлайн-генерацию. Необязательный fixed pool выбирается с возвращением; его построение не исключает повторения между training-примерами. Наш адаптер использует отдельные детерминированные RNG split, глобально уникальные строки и существующий последовательный циклический loader без shuffle. После обхода пула примеры повторяются. Эквивалентность протокола обучения источнику не заявляется.

Seed 1337 преобразуется через `SeedSequence(1337).generate_state(3)` в отдельные seed для train/val/test. Для каждого split используется буквальный однострочный вызов source RNG. Все 102000 строк отдельно воспроизведены через настоящие `_sample_one` и `collate` закреплённого источника. Входы и метки совпали. SHA256 строк подтверждают отсутствие повторений и пересечений. Это проверка данных, не результат обучения модели.

## Метрики

Основные метрики — точная accuracy и `count_nmae`. Argmax выполняется по всему словарю. Ограничение argmax только классами запрещено.

Для NMAE: raw_count = predicted_token - CLASS_LOW; clipped_count = clip(raw_count, 0, max_count). Затем mean(abs(clipped_count - true_count)) / (n/m + 1). Здесь знаменатель равен 17, как в источнике. Он не подменяется математическим ожиданием 1+(n-1)/m=16.96875. Вне диапазона классов exact prediction остаётся ошибкой, даже если clipping уменьшает NMAE. Сохраняются также raw MAE, clipped MAE, clipped bias и число предсказаний вне диапазона.

CE агрегируется суммой по всем 1000 ответам, включая хвостовой batch; NMAE тоже взвешена ответами, а не batch. Метрика BPC для Count не выводится. Во время обучения сохраняются прежние CE/accuracy validation; task-specific NMAE выдаёт публичный evaluator на выбранном split.

Константные baselines выбираются только по train: mode=17 и округлённое среднее train=17. Для test accuracy=0.106 и NMAE=0.18388235294117647. Ожидаемая accuracy случайного ответа из train prior равна 0.07197909. Uniform по полному словарю и по исходным count-классам приведены отдельно, это не основной содержательный baseline. Oracle даёт 100%. График `count-distribution.png` показывает данные, не качество обученных моделей.

## Общая модель и бюджет

Обе семьи: 4 блока, width=128, 4 головы, context=512, batch=32, seed=42; AdamW LR=0.001 constant, WD=0.1; FP16 с FP32 master-параметрами, compile=true, cap=128, early stopping выключен. Словарь 546 одинаков. Новые задачи обучаются с нуля. Старые веса MQAR/Tiny не используются.

`experiments/selective_count/v1/{classic,deltanet}/seed_42.yaml` — предварительные конфиги. Поле 1e14 является техническим placeholder, не выбором бюджета и не разрешением запуска. `protocol.json` и `budget.json` явно содержат launch_allowed=false. Бюджеты 1e14/1e15/1e16 рассчитаны действующим estimator; подробности включают шаги, ответы, покрытие пула, overshoot, cadence и количество FULL snapshots. В pinned source-файлах нет рецепта или горизонта обучения; численная эквивалентность reference exposure не заявляется.

Предложение первого полного пилота: 1e15 на каждую семью. Оно обеспечивает полный обход train и примерно 2.4–2.8 прохода вместо менее 28% пула при 1e14. Это ограниченный первый пилот, не обещание сходимости. Выбор делает родитель до облачного запуска. Общий бюджет внутри пары обязателен; одинаковый бюджет для всех четырёх разных задач не требуется. Общий усреднённый score не вычисляется.

## Публичные команды

Из корня проекта, без изменения зависимостей:

```sh
uv run --no-sync python -m compare_attention.cli.prepare_selective_count --output local/datasets/selective-count-v1
uv run --no-sync python -m compare_attention.cli.train --config experiments/selective_count/v1/classic/seed_42.yaml
uv run --no-sync python -m compare_attention.cli.evaluate --checkpoint PATH/model.pt --data local/datasets/selective-count-v1 --split test --device cpu --dtype float32 --output NEW.json
```

Команда train выше показывает интерфейс; предварительный production config не является разрешением выполнить обучение. Для инженерной проверки использован отдельный config CPU/eager/FP32/disabled tracking, с двумя обновлениями на настоящем production dataset и прежними размерами модели. Проверены FULL snapshots, изменившиеся параметры и независимый test на 1000 строк. Две итерации дали test accuracy=10.6%, равную константному baseline; это не научный пилот и не свидетельство обучения счёту. DeltaNet CPU evaluator явно отклоняется, численное исполнение Delta на CPU не имитируется.
