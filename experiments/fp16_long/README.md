# FP16: длинный бюджет 10^17 FLOPs

Это отдельная серия. Исходные конфиги `experiments/fp16/` не изменены.

## Конфигурации

- `classic/seed_42.yaml`
- `classic/seed_6767.yaml`
- `classic/seed_696969.yaml`
- `deltanet/seed_42.yaml`
- `deltanet/seed_6767.yaml`
- `deltanet/seed_696969.yaml`

Единственное отличие каждого YAML от одноимённого baseline в `experiments/fp16/`:

```yaml
schedule:
  train_flops: 100_000_000_000_000_000
```

Batch 8, FP16 AMP/FP32 параметры, текущие реализации, модель, оптимизатор,
данные и сиды сохранены. FLOPs считаются по `algorithmic_matmul_conv_v2`.
Ожидается 40 422 обновления classic и 41 675 обновлений DeltaNet.
Каждый запуск начинается с исходной инициализации своего сида, не с весов короткой серии.

## Этапы

Сначала разрешены только два пилота: classic/42, затем deltanet/42.
Остальные четыре конфига подготовлены, но не запускаются автоматически.
Решение о повторах принимается после оценки кривых обучения пилотов.

Перед публикацией проверяются неизменность production source и конфигов,
ранее пройденные T4 проверки устойчивости и артефакты неизменяемой серии.
Один общий подготовленный KV dataset переиспользуется после сверки manifest.
Численный сбой или несовпадение артефактов останавливает очередь.
Таймаут ожидания каждого kernel — 43 200 секунд, включая очередь.

## Наблюдения и ограничения

- Loss записывается после каждого обновления; validation — каждые 100 обновлений и в конце.
- Метрики содержат накопленные FLOPs; они позволяют сравнить ранние и поздние участки.
  Порог 10^16 не обязан совпадать с точкой validation; не выдавайте ближайшую точку за точную.
- **Текущий trainer сохраняет веса только в конце запуска. Промежуточных checkpoints
  и автоматического resume нет.** Это ограничение не исправляется новым YAML.
- FP16 GradScaler может увеличивать scale во время длинного обучения. Исходная политика
  abort-on-skipped-update сохранена; отсутствие пропусков на короткой серии не гарантирует
  их отсутствие на новом горизонте.
- Время обучения не является критерием качества. Проверяйте val loss и accuracy.

Матрица YAML проверяется тестом `tests/compare_attention/cli/test_fp16_long_matrix.py`:
полный набор шести файлов, полное равенство baseline кроме бюджета и реальный parser.
Локальный оператор и offline-тесты очереди находятся в Git-ignored
`local/experiments/fp16-long/`; manifest и результаты — на E: в HermesArtifacts.
